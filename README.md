# 🌦️ سرویس آب‌وهوای خودروهای خودران (WeatherService)

سرویس WeatherService یک API مبتنی بر NET. است که برای خودروهای خودران طراحی شده. این سرویس اطلاعات آب‌وهوای لحظه‌ای رو بر اساس مختصات جغرافیایی خودرو از یک API خارجی دریافت می‌کنه، داده خام رو در پایگاه داده محلی SQLite ذخیره می‌کنه و همون داده رو بدون تغییر به کلاینت (مثل سیستم تهویه، موتور یا ماژول مدیریت انرژی) برمی‌گردونه.

این پروژه با رعایت کامل اصل KISS و معماری تمیز طراحی شده تا پایداری آن برای یک دوره ۲۰ ساله بدون نیاز به مداخله انسانی تضمین شود.

## ✨ ویژگی‌های کلیدی و تحمل خطا

- مختصات پویا (Dynamic): سرویس مختصات `lat` و `lon` را از کلاینت می‌گیرد. اگر ارسال نشود، به صورت پیش‌فرض از مختصات برلین استفاده می‌کند.
- مقاومت در برابر ۳۰٪ خطای شبکه: با توجه به نویز و قطعی‌های بی‌سیم در خودرو، سرویس به گونه‌ای طراحی شده که در صورت قطعی اینترنت از کار نیفتد.
- پشتیبان‌گیری محلی (Fallback): اگر ارتباط با API خارجی برقرار نشود، سرویس بلافاصله آخرین داده موفق ذخیره‌شده در دیتابیس SQLite را بازمی‌گرداند.
- مدیریت خطای شفاف: اگر اینترنت قطع باشد و دیتابیس هم خالی باشد، مقدار `null` بازگردانده می‌شود.
- تضمین زمان پاسخ‌دهی (حداکثر ۳ ثانیه): زمان‌بندی سخت‌گیرانه‌ای پیاده‌سازی شده که بودجه زمانی را بین API (۱.۵ ثانیه)، ذخیره‌سازی (۰.۵ ثانیه) و بازیابی از دیتابیس (۱ ثانیه) تقسیم می‌کند تا کلاینت هرگز پشت خط منتظر نماند.
- یکپارچگی داده‌ها: داده‌های دریافتی به صورت کاملاً خام (Raw JSON) ذخیره و بدون هیچ تغییری به کلاینت بازگردانده می‌شوند.
- پاک‌سازی خودکار دیتابیس (Data Retention): یک سرویس پس‌زمینه (`BackgroundService`) به صورت دوره‌ای رکوردهای قدیمی‌تر از ۲۴ ساعت را پاک می‌کند تا حافظه خودرو در طول ۲۰ سال پر نشود.

## 🏗️ معماری سیستم

پروژه با استفاده از Minimal API و معماری لایه‌ای تمیز پیاده‌سازی شده است:

- Endpoint (`Program.cs`): مدیریت درخواست‌های HTTP، اعتبارسنجی ورودی‌ها و اعمال محدودیت زمانی.
- Orchestrator (`WeatherOrchestrator`): مغز متفکر سیستم که تصمیم می‌گیرد داده را از اینترنت بگیرد یا از دیتابیس، و بودجه زمانی ۳ ثانیه را مدیریت می‌کند.
- External Service (`ExternalWeatherService`): ارتباط با API خارجی (Open-Meteo) با استفاده از `HttpClient` و مدیریت دقیق خطاهای شبکه.
- Database Service (`DatabaseService`): مدیریت پایگاه داده با استفاده از Entity Framework Core.
- Background Service (`DbCleanupService`): پاک‌سازی دوره‌ای داده‌های قدیمی برای جلوگیری از رشد بی‌رویه دیتابیس.

## 🚀 نحوه استفاده از API

### دریافت اطلاعات آب‌وهوا

`GET /api/weather`

پارامترهای ورودی (اختیاری):
- `lat`: عرض جغرافیایی خودرو (مثلاً `35.6892`)
- `lon`: طول جغرافیایی خودرو (مثلاً `51.3890`)

(نکته: هر دو پارامتر باید با هم ارسال شوند یا هیچ‌کدام. مختصات نامعتبر با خطای 400 رد می‌شوند).

نمونه درخواست:
```http
GET https://localhost:xxxx/api/weather?lat=35.6892&lon=51.3890
```

نمونه خروجی (داده خام JSON):

```json
{
  "latitude": 35.667652,
  "longitude": 51.403595,
  "generationtime_ms": 0.43129920959472656,
  "timezone": "GMT",
  "current_weather": {
    "time": "2026-10-30T22:15",
    "temperature": 15.5,
    "windspeed": 7.7,
    "weathercode": 80
  }
}
```

## 🧪 تست‌های خودکار

پروژه مجهز به تست‌های واحد و یکپارچه (xUnit & Moq) برای سناریوهای بحرانی است:
- قطعی اینترنت و بازگشت به کش (Cache Fallback)
- قطعی اینترنت و خالی بودن دیتابیس (بازگشت `null`)
- شکست عملیات ذخیره‌سازی و بازگشت به داده‌های قبلی
- بازیابی صحیح داده‌ها بر اساس مختصات دقیق

## نحوه اجرای پروژه

### پیش‌نیازها

- [NET 10 SDK.](https://dotnet.microsoft.com/download)
- Entity Framework Core CLI (`dotnet tool install --global dotnet-ef`)

### مراحل اجرا

۱. دریافت پروژه از گیت‌هاب:

```bash
git clone https://github.com/mohammadmovahhed/WeatherService.git
cd WeatherService
```

۲. ساخت دیتابیس محلی:

```bash
dotnet ef database update
```

۳. اجرای برنامه:

```bash
dotnet run
```
